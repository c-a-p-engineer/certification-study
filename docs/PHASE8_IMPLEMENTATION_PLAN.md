# Phase 8 — MASTER QUEST 実装計画

**状態:** 仕様合意済み・開発着手前（2026-10-25）。ここは実装順序・受入テスト・PR境界の計画であり、ユーザー体験の契約は [docs/SPECIFICATION.md §9](SPECIFICATION.md#9-phase-8--master-quest合意済み将来仕様未実装) が唯一の正本。
**前提:** 7.0b Issue #23は完了。現行348問、10問×4分野ボス、10問のB/A/S基準、既存XP、Daily Five、復習エンジン、SVG、ローカルセーブを生かす。

## 1. 開発上の重要な決定

1. **学習イベントを単一の真実とする。** BOSS INTELを専用の報酬エンジンにはせず、既存 `answerHistory` と版管理したCONCEPT MAPから読み取り専用で導出する。新しいXP計算・レベル・勲章・戦闘HP計算はしない。
2. **攻略情報は権利ではなく観測情報。** 計測可能な初回正解、誤答回復、異なるローカル暦日での期限到来復習成功を表示する。ゲーム進行のロックやボスの採点調整には使わない。履歴・分類の欠落は「未確認」。
3. **旧データは既存の意味を保つ。** 問題ID・模試65問130分・進捗/XP/ボス最高成績・遠征報酬・v1セーブ/模試保存・v1/v2バックアップ・Web Locks保護は維持。CONCEPT MAPは静的コンテンツなので初期版では学習者保存形式を増やさない。
4. **情報と演出の分離。** 集中モードは見やすさが優先。通常モードではボスの攻略情報、敵のSVGやクエストの演出を表示できるが、どちらも同じ回答トランザクションを通る。
5. **独立した有識者承認と混同しない。** AI/エンジニアリング検査、AWS公式文書へのリンク、CI合格は人間による独立承認の代替ではない。現在の独立承認は0/348で、関連Issues #7/#9/#10/#14は別途継続。

## 2. コンポーネントとデータフロー

```text
348問と公式AWS参照 ──> CONCEPT MAP（静的・版管理・確認済みのみ）
                                 │
ローカル answerHistory ──> 純粋 evidence selector ──> BOSS INTEL（読み取り専用）
（模試イベントを除外）                                  │
                                                       ├── 4ボスの攻略情報（任意表示）
Daily Five / SMART / RECALL / MISSION ────────────────┘
              │
              └── 既存 applyStudyAttempt ──> 既存XP・復習・敵HP・保存
                                                           ↑ 変更禁止
10問 BOSS RUSH ──> 既存 bossOutcome / recordBossVictory ───┘
```

- **概念カタログ:** 提案パス `src/conceptCatalog.ts`。型は `ConceptId`, `bossDomain`, `label`, `officialReference`, `mappingVersion` を含める。新規問題IDは発行しない。
- **設問と概念の対応:** 提案パス `src/conceptQuestionMap.ts`。安定した `questionId` → 確定済み `conceptId[]`、根拠と確認ステータス。**候補マッピングを本番カウントに混入させない**。
- **純粋集計:** 提案パス `src/bossIntel.ts`。入力 `catalog, map, answerHistory, now`、出力 `BossIntelSnapshot`。表示に適した中間形にする。ローカルストレージ・日時の取得・React依存を持たない。
- **読み取り専用UI:** 提案パス `src/BossIntelPanel.tsx`。既存 `BossBoard.tsx` から開閉できる。トップのDaily Fiveや質問カードには重たい情報を追加しない。
- **表示配線:** `src/main.tsx` と `HomeSecondaryPanels.tsx` から必要な計算済み情報とcallbackを渡す。既存の `BossBoard`/解答コントローラー/報酬確定は変更を最小化する。
- **設計ラボ:** 既存 `designLab` の3段階判断と単問復習は、出所が異なるため初回リリースの集計対象外。必要なら後続PRで独立に概念対応を追加する。

### 計測詳細・例外

- カウント単位は、1つの概念×1つの問題ID×1つの証拠区分につき最大1。異なる概念に紐づく設問は、それぞれへ関連づけるが同じ概念の重複は増やさない。
- `firstAttempt && correct && !exam` → 観測された初回正解。`recovery && correct && !exam` → 観測された誤答克服。
- 異なる日付の、同一IDの非模試先行イベントと、後日の `due && correct && !exam` がそろう場合だけ期限到来再想起として計上。1/3/7/14日の計数は先行イベントとの差を比較し、各閾値を満たした結果と対象数を記録する。旧保存から当該イベントを復元しない。
- 日付は既存 `localDateKey` とイベント中の検証済み日時を使う。DST・日付跨ぎ・未来時刻・不整合な履歴・3,000件上限・重複・順序逆転への検証を行う。
- 現行 `answerHistory` は非模試のボス/遠征回答を完全に区別する属性を持たないため、初期版の証拠は**非模試の学習回答全般**と明示する。今後モード別に厳密分離するなら、任意フィールドを別PRで追加し、旧イベントは出所不明と扱う。既存記録からモードを推測しない。
- 分子だけで実力のパーセンテージを出さない。各概念の「対応済み設問数」と「記録から確認できた異なる設問数」を分けて出し、未分類・履歴なしを空値のまま表示する。
- ボス挑戦**前**に攻略情報を表示し、挑戦**中**にはINTELの変動表示を行わない。結果表示では最新の履歴を再集計してよい。ボス挑戦前の画面表示を保存済みミッションへ無理に格納せず、途中復帰時の旧セーブ互換を維持する。

## 4. リリースとロールバック

1. 本PRは**計画文書のみ**。動作を変えない。実装PRごとに仕様§9とテストをその場で更新し、レビュー可能な短い差分にする。
2. 8.1〜8.2では純粋関数・静的カタログを先に開発し、画面には出さない。8.3以降で任意表示を解禁しても、ユーザー進捗を更新する経路は既存のものだけ。
3. 不正マッピング・表示異常を検出した場合はINTEL表示を停止できるようにし、復習/採点/XPなど学習自体の機能は動作を維持する。既存保存データを削除・再計算しない。
4. CI成功のみでは端末パフォーマンス・アクセシビリティの実機確認とはならない。ユーザーの指示どおり、ブラウザE2E・実機Android/Brave・独立したAWS有識者によるサインオフは**未実施**として明記する。

## 5. 出荷判定と観測目標

- **機能:** 4ボス×10問・7/9/10の合格条件・報酬・模試隔離・Daily Five最大5問を退行させない。
- **品質:** 最初の重点20〜30問に、採用した概念IDとAWS公式参照、各選択肢の根拠がある（独立人間承認とは別）。
- **可読性:** 長い問題文で原文・設問IDが変わらず、次行を追いやすい表示が使える。UI上に根拠不明の「理解度100%」等を出さない。
- **成長:** 異なる問題・後日の復習成功を正確に計上し、二重回答や未観測データから証拠を創作しない。
- **運用:** 貼り付けられた古いPWA版・保存済みセッションが復帰し、全CI・Pagesが通ること。実機の快適性向上は計測されるまで仮説として扱う。
