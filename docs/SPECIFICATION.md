## 0. 新しい標準画面 — REBORN (2026-11-21)

### 起動・表示

- `index.html` は `src/entry.ts` から `src/reborn/index.tsx` の **REBORN OVERDRIVE** のみを起動する。旧UIの切替導線は廃止した。旧ソースと既存進捗・称号・ボス・遠征・模試途中保存のデータは削除しないが、新画面に未移植の古い進行途中の再開機能は提供しない。
- **標準ホームの主操作はQUEST RUN**（3ステージ・計15問）とする。最初の大きなカードはルート選択つきの冒険を開始し、続くQUICK PLAYにBLITZとDAILY CODEの2カードを並べる。XP・解答数・正答率はコンパクトに表示し、従来のDAILY FIVE・苦手5問・ランダム5問・分野別10問・65問模試は折りたたみ可能な**ACADEMY**にまとめる。常時表示のナビゲーションはホーム・成長・設定の3項目とし、スマホで重要な操作を最初に示す。
- 問題画面は **設問 → 選択肢 → 答え合わせ → 正解と理由 → 次へ** の単一路線。元の安定問題IDを表示し、用語図鑑、公式AWS参照、必要時の選択肢比較を保つ。択一・複数選択の正解は `gradeAnswer` の完全一致で判定し、選択肢の表示順と見えるA/B/Cラベルを一致させる。正解・解説は確定前に表示しない。
- **問題中の用語図鑑（モバイル）:** 新標準画面では用語パネルを初期状態で閉じ、1行の「用語を確認・件数」だけにする。タップで展開した一覧は各行に**用語名＋日本語の意味**を簡潔に並べ、詳しい正式名称・読み方・使いどころは用語単位で展開する。用語が4件でも大きな空白を挟まず縦に一覧できる。問題の回答選択肢を初期スクロールから不要に押し下げない。用語の正規データと選出順、採点・記録には触れず、旧コンポーネントの既存利用箇所を変更しない。スマホ320/360/400pxで、詳細を開くまで用語1件あたり原則1行〜2行の密度、44px以上の操作領域、キーボード展開を満たす。
- **高速解答フロー:** 確信度の質問・選択を完全に廃止する。択一問題は選択肢ボタンを1回押すだけで即採点・正誤/解説を表示する（中間の「答え合わせ」ボタンなし）。複数選択問題は誤タップを避けるため、複数選択後に限って1つの「選択した答えを確定」ボタンを使う。模試の択一もタップで即次問（正誤・解説は試験終了まで非表示）、複数選択だけ確定ボタンを使う。二重タップや重複送信はイベントロックと正規のreceiptで防ぐ。押した後は結果の冒頭へ移動し、解説後は「次の問題へ」を1回押すだけとする。
- **読みやすさ:** 以前の「文ごとに読む」を新標準画面で復活させる。原文の句読点・全文・問題ID・選択肢の意味は改変せず、文ごとに視覚的区切り・行間を提供する（既存 `splitReadingSentences` を流用）。問題文の表示サイズは「小／標準／大／特大」等を学習中に切り替えられ、既存 `readTextScale/saveTextScale` と `readReadingGuide/saveReadingGuide` の保存値を使用する。長文問題・選択肢・解説の可読性を優先し、320/360/400pxでも横スクロールしない。読みやすさの設定で採点・出題順・試験タイマーを変えない。
- 回答後の正誤フィードバックと任意のSEは実際の採点結果の直後に提示する。XPと敵ダメージは既存ロジックの実結果だけを表示し、連打で増えたように見せない。設問回答時に別の報酬経路を作らない。
- 5問または10問の結果では、今回の正答数・獲得XP、誤答問題と正しい選択肢の説明を示し、**「今日はここで終了」** を主操作とする。強制的な再スタートはしない。
- 4分野の成長画面は既存の `buildDomainIntel` を参照し、観測問題・復習期限・苦手・別日復習成功を示す。過去にイベント履歴のない利用者へ不正な習得率を作らない。
- 設定に効果音/BGM、振動・FX強度、動き軽減、既存互換バックアップのJSONエクスポート・検証付きインポートと中断復元のロールバックを設ける。外部サーバーへ学習データを送らない。

### 高密度演出 — OVERDRIVE FX（2026-11-21）

- 学習画面の新デフォルトは**強い視覚演出・音・振動**を連動させた高速フローとし、標準UIから「旧版」案内・`?legacy=1` 切替を廃止する。旧UIのソースや従来データを自動削除しない。従来の復旧導線は新UI内の検証済みバックアップ復元／復元ジャーナル回復ボタンで代替する。
- ユーザー操作ごとに短い選択フィードバックを与える。採点が確定した**実際の**正誤・連続正解・敵への実ダメージ・実討伐に応じて、独立した演出計画からテキスト・パーティクル・フラッシュ・画面内シェイク・既存WebAudioオリジナルSE・振動パターンを同期させる。3連続正解以上はCOMBO表示、実際に敵を倒した時のみMONSTER DOWN表示。純粋な演出はXP/HP/回答履歴や模試報酬を更新しない。
- ノーマル学習では解答直後に結果・正解理由を表示し、演出は短時間で収束させ、操作は演出待機なし。**演出を見てからでなければ次へ進めない**という制限を設けない。結果へ進むボタンは常に押せる。模試では正誤・正解・連続正解演出を表示せず、ニュートラルな回答SEと振動だけを許可する。
- 既存の`AudioDirector`（WebAudioによる合成SE/BGM）と`haptics.ts`（Web Vibration API）を使い、画面上で効果音・BGM・振動強度・演出強度を変更できる。操作は自発的なクリックの起点で音声解除を行い、ブラウザ自動再生制約に従う。BGMの再生場所をHOME / MISSION / EXAM / RESULTで切り替える。端末が振動をサポートしない場合は静かに省略する。
- アニメーション、粒子、光量、シェイクには明確な上限を設ける。OSの`prefers-reduced-motion`またはアプリの動き軽減時には画面効果と振動を停止し、文字による正誤・解説はそのまま維持する。点滅の連続反復・急激な全面反転・無限シェイクは行わない。
- 追加の旧UIへの誘導を撤去し、既存学習キー、問題キー、復元ジャーナル、エクスポートおよび復元機能を**新画面から完結**させる。保存競合時は新規回答を停止し、診断JSONの退避と読み直しを優先する。進行中の旧形式ミッション／模試保存データを削除せず維持するが、途中再開自体は本改修の対象外。
- 演出の種類・タイミング・妥当性は自動テストとビルドで確認する。実際の音・振動・表示の気持ちよさは実機検証なしに立証したとは記載しない。

### CUSTOM AVATAR & COLLECTION — 自分の姿と装備品（2026-11-22）

- REBORNのモンスターが黒い原因は、`enemyVisual.css`のカラー/目/アウトライン指定が旧`.app`にのみスコープされ、`.reborn`ではSVGのデフォルト黒塗りが使われるため。**新旧の画面双方に同じ既存カラー指定を適用し、全9種のモンスターを元の色で表示する**。既存の`MonsterArt`の正規ID・HP表示・討伐条件は変えない。
- ホームの一番上に**自分のキャラを常時見せる**。QUEST RUN/BLITZ/DAILY CODEのキャラクター表示にも同じ装備スタイルを渡す。表示は独立したSVG（髪色・服色・武器・頭飾りの4スロット）。外部画像・有料素材・サーバー接続は増やさない。
- アイテム取得は`answerHistory`で実際に記録された**異なる問題IDに対する非模試の正解数**に従う、固定の非ランダムな見た目解放。初期装備は無料。複数段階の必要数を明示し、達成済みは「獲得済み」・装備中は「装備中」と表示。失敗や連続ログインの途絶で没収しない。同日同問題・模試・ラン内スコア・ボス演出は追加解放の根拠にしない。上限3000件の履歴以外の旧データは推測で復元せず、未観測を未観測と扱う。
- マスターが選択したスタイルは**既存progressのオプション`avatarAppearance`**として保存し、既存の保存競合ガードを通す。バックアップは既存progressのallowlistをそのまま利用。無効な値/未解放のアイテムは無償の標準スタイルへ戻し、旧進捗の取得・バックアップ互換性を損なわない。学習XP、学習報酬、問題ID、通常キャンペーンHPを書き換えない。
- 320/360/400pxの画面でメインクエスト開始操作の発見性を維持。ホームのキャラクター表示はコンパクトにし、細かな着せ替え操作は任意の展開式パネルに配置する。アイテムボタンは44px以上、所持状況・必要問題数は色に頼らずテキスト表示。動き軽減・FX OFFでも静的キャラと所持品が見える。
- 受入テストは全モンスターの配色セレクタ、各装備の視覚差・解放閾値・無効値のfallback・誤答/同日反復/模試の解放不可・保存/バックアップ互換性、ホーム/QUEST/BLITZ/DAILY CODEでの装備表示、SSR描画、既存ビルドを確認する。端末実機の視認性は未実施なら未確認と明記する。

### QUEST RUN 3D表示の安定化と敵3D試作（2026-11-22）

- プレイヤー3D表示中に旧SVGがちらつく不具合を修正する。原因はQUEST RUNの「問題」と「解説」で別々の`BattleStage`をレンダリングし、`QuestHero3D`の`loading`状態で旧SVGを可視化していたこと。**問題から解説、次の問題へ移る間は同一の`BattleStage` DOMと3Dコンテキストを維持**し、3D選択中はロード中も旧SVGを表示しない。初回のモデルロード中はテキストで「3D準備中」と表し、明示的2D選択か3D失敗時のみ従来SVGへ戻す。
- 同じ作者の`KayKit Character Pack: Skeletons 1.0`（CC0）を採用し、**敵もQUEST RUNの3D選択中は3Dの実モデルで表示**する。ステージ1はSkeleton Minion、ステージ2はSkeleton Warrior、ボスはSkeleton Mageの3種類を選ぶ。敵名・ドメイン・HPは既存のゲーム固有名のままで、**3Dモデルは見た目の試作**（元の敵の固有造形ではない）と明記する。
- 3Dモデルのクリップに実際に存在するIdle/Attack/Hit/Death系のアニメーションを選択し、イベントに同期する。正解が記録され敵へ実ダメージが発生したときだけ被弾、敵HPが0になった時だけ撃破、誤答時だけ反撃させる。描画中断や3D失敗で学習XP・ランHP・敵HP・問題進行・判定経路に影響を与えない。
- **プレイヤー3D＋敵3Dは共通のThree.js遅延ロード・独立した描画領域**で描き、HOME・BLITZ・DAILY CODE・模試へGLBを追加ロードしない。大きなGLBはGit管理しないで固定commitからビルド時に取得し、Git blob SHAとGLB構造・外部参照なしを検証してVite公開物に同梱する。利用者のブラウザからGitHubへ直接取りに行かない。初回オフラインやモデル失敗では2D、FX OFF/動き軽減/WebGL非対応では2Dを使う。
- ステージ中の再マウントを防ぐこと、読み込み中の旧SVG非表示、双方のモデル割当・CC0素材検証、3Dの正誤と撃破、2D切替、キーボード/320px/動き軽減、既存テスト・`npm run build`、PRおよびPages CIを受入条件とする。Android実機のFPS・視覚品質は未検証なら明示する。

### QUEST RUN 既製3Dキャラクター試作 — KayKit Mage（2026-11-22）

- QUEST RUNの問題画面および解説画面で、既存の左側プレイヤーキャラ表示を**KayKit Adventurers 1.0のCC0既製Mage 3Dモデル**へ置き換えて試せる。既存の戦闘モンスター、HPバー、与ダメージ、回答操作はReact DOMに残す。全画面3D化せず、キャラの小領域にThree.js WebGLを**遅延ロード**する。ゲーム起動、HOME、ACADEMY、模試、BLITZ、DAILY CODEではこのGLBをロードしない。
- QUEST RUNでは3D表示を初期候補とし、戦闘HUDの**「3D / 2D」手動切替**でいつでも元のSVG表示へ戻れる。3Dで使うモデルは現在の装備アイテムの外見に未対応のため、**KayKit Mage試作モデル**である旨を明示する。2Dへ戻した場合は従来どおり装備カラー・衣装・武器が反映される。
- 3Dは**実際の採点後イベントだけ**で待機・攻撃・被弾アニメーションを動かす。追加XP・学習履歴・ボスHP・QUESTランのダメージロジック・解答の受付を変更しない。レンダリング初期化やアニメーション終了を待ってから回答する仕組みを作らない。
- WebGLが利用不可、モデル読み込み失敗、GPUコンテキスト喪失、FX OFF、OS/アプリの動き軽減時は軽量な既存SVGに**自動フォールバック**する。Canvasは操作イベントを横取りせず、破棄時はrequestAnimationFrame/WebGLループとobserver/rendererを停止・disposeする。画面外・非表示中はループを停止する。表示は320/360/400pxで問題文やタップ領域を押し潰さない。
- 3D素材は著作者Kay Lousbergの**KayKit Character Pack Adventurers 1.0（CC0）**から、GitHub上の特定commitとGit blob SHAを固定してビルド時に取得・検証し、アプリ配信物に含める。**ユーザー端末がGitHubへ直接モデルを取得しに行かない**。手動アップロード・画像制作・実行時外部API・追加課金は不要。モデルの約3.6MBはQUEST RUN表示時にのみ要求する。ビルド時の外部依存が検証できなければリリースしない。
- オフラインで3Dを初めてロードする場合は既存SVGが使える。通常のアプリシェルのprecacheに大型3D素材を無条件追加しない。従来のオフライン学習、FX設定、読書モード、バックアップを維持する。
- 受入検査: 許可済みCC0素材の正規取得・blob一致、配信パスの正当性、3Dの遅延ロード、2D切替、SSRとフォールバック、採点の無変更、GPU/画面非表示の終了処理、モバイル/動き軽減CSS、既存`npm run build`およびPRとPages CI。端末実機でのFPS/品質/触感は別途未検証とする。

### CHARACTER BATTLE — 戦況が分かるキャラクター表示（2026-11-22）

- QUEST RUNの問題画面と回答後レビューに、**プレイヤー＋既存モンスターSVGの両方が常時見えるコンパクトな戦闘ステージ**を表示する。頭上のLIVE REACTORだけに依存せず、問題文と選択肢に重ならない固定高さの小さな戦闘エリアとして配置する。敵IDは選択したルート／最終ボスから決定する。通常学習の正規キャンペーンとは別の、一周のゲーム用キャラクターである旨を区別する。
- プレイヤーは独自の軽量SVGアバターを**標準フォールバック**として保持し、QUEST RUNで3Dが有効かつ利用可能なら上記KayKit Mage試作を代わりに表示する。従来の待機・構え・攻撃・被弾・勝利の視覚状態は両方式で保つ。敵は既存`MonsterArt`を流用する。**正解確定 → ラン内攻撃ダメージ → 敵HP減少 → 被弾／撃破演出**、誤答は**プレイヤー被弾・従来のランHP減少**の因果関係を一致させる。結果を確定する前に正誤を示唆しない。連続正解と選択済みスキルで実際のゲーム内ダメージが変わるときだけ、攻撃を強調する。
- ステージ別の敵HPは【第1:95、第2:135、ボス:190】。正答時のダメージは【第1:23、第2:29、ボス:39】を基準とし、3連続以上は+6、`amplifier`スキルはダメージ1.5倍、`combo`スキルは3連続以上で追加1.25倍（端数四捨五入）とする。誤答の敵ダメージは0。敵HPは0未満にならない。敵が途中で倒れても、当該ステージの5問は完了まで解ける。最終5問終了時に**敵HPが0かつランHPが1以上の場合だけボス撃破と表示**し、HPが残る場合は未討伐と明記する。第1・第2ステージは敵HPが残ってもルート突破・スキル選択へ進める。
- この敵HP・与ダメージ・キャラクター演出はQUEST RUNラン内の独立したゲーム進行である。保存されるAWS学習XP、正答証拠、9体の通常キャンペーンHP、分野別ボスのB/A/Sメダルと混同させず、独自の学習報酬計算や追加の回答書込を実装しない。`applyStudyAttempt`と一意receiptが正規書込経路のまま。ボス未討伐は不正解の隠蔽にも合格推定にも使わない。
- BLITZではプレイヤーの小型アバターをリアクターの横に置く。正答・誤答で一瞬の動作が変わっても、即時次問へ進む流れを停止しない。DAILY CODEでは同じアバターをナビゲーターとして使い、選択・対応成功・ミスの実イベントに同期して反応させる。模試・通常学習は問題文の可読性と省スペースを優先し、戦闘キャラクターの常設を強制しない。
- 既存の2D戦闘はSVGとCSS animationの軽量表示を維持する。上記の任意3Dキャラ試作のみ、既存のThree.jsと固定CC0 GLBを遅延ロードする（新規の有償サービス・常駐タイマー・回答経路は増やさない）。FX OFFでも戦況を表す静的キャラクターとHP値は残す。FX HIGHでは演出を簡略化し、FX MAXIMUMで演出を増やす。OS動き軽減とアプリ動き軽減は待機と攻撃・被弾のアニメーションを停止する。被弾・攻撃はテキストでも表示し、タップ領域・320px画面幅・任意終了を妨げない。
- 受入条件: 全てのルート・ステージの相手、与ダメージ・HP下限、コンボ／スキル係数、ボス未討伐時の非勝利、学習報酬の無変更を純粋関数のテストで確認。React SSRでQUEST RUN、BLITZ、DAILY CODEのキャラクターを確認し、CSSの動き軽減と必須PR CIの`npm run build`を通す。Android実機の視認性とフレームレートの検証は未実施なら未確認と報告する。

### LIVE REACTOR — 解答中の持続的アーケード演出（2026-11-21）

- 単に正解時に閃光を出すだけでなく、**設問を読んでいる間も**薄く動くエネルギーコア、回転リング、低密度の流星粒子、背景を移動する光線を表示する。共通表示コンポーネントを通常学習、BLITZ、DAILY CODEで再利用し、QUEST RUNでは2026-11-22追加のキャラクター戦闘ステージが優先表示を担う。専用の小型領域（最大約100px）へ閉じ込め、問題文と選択肢への描画重ね合わせ・オーバーフローを禁止する。

### DAILY CODE — 一人用サービス対応パズル（2026-11-21）

- 新標準ホームのSOLO ARCADEに「DAILY CODE」を追加する。4つの**AWSサービス名**と4つの**既存の日本語定義**を、利用者が対応付ける。一問ごとに「説明を選ぶ→サービスを選ぶ」の2アクションで進めるため、従来の四択を横に並べた形式とは異なる。誤対応は正解の開示や強制終了にせず、再挑戦可能とし、正しく一致させると既存の詳しい注記を表示する。
- 出題は既存`termGuide.ts`の精選済みの用語・意味を再利用する。曖昧な同義語を1セットに混ぜないため、プリセットの4語セットと日付ごとの固定順序を使う。**説明とサービス名の左右の並びは、どの行でも正解同士が対応しない順列（固定点なしの置換）にする。** 独立した2回の乱数シャッフルだけではこの条件を保証しないため使わない。日付に基づく決定的な順序生成で、同一日は同一問題と同一配置とし、上から順に同じ行を押すだけで正解できないことを保証する。年度更新を含む事実確認と独立QAを通過したと偽らない。日付は端末ローカル日付を使用する。

- 受入テストでは4語の固有性、同日における同一パズル、答えの対応、**全日付で同じ行の組み合わせが正解にならないこと（少なくとも複数年の日付を網羅検査）**、一度一致したカードの再回答防止、正解時の説明表示、誤答時の解答非開示と学習XPの非更新を検査する。

### モードと最初の遊び

- 新標準ホームはQUEST RUNを最上部のヒーロー操作とし、BLITZとDAILY CODEをその下に配置する。架空NPCトーナメントは導入しない。既存のDAILY FIVE/ACADEMY/65問模試は折りたたまれたACADEMYから利用できる。
- **QUEST RUN:** 3ステージ・各5問、各ステージ開始前に**自分で2つのルートのどちらかを選択**する。1〜2ステージはテーマを選び、各ステージ終了後に3種類のうち1つのラン内スキルを選ぶ。3ステージ目は各分野から選出したBOSSラウンド。毎回異なる問題とルート選択により再プレイ性を持たせる。ランHPは100で、誤答で15減り、0になると敗北。スキルは一時的なラン内スコア・HP・ラン内の敵への攻撃ダメージとゲーム演出だけへ効き、問題キーや学習XPを変えない。攻略は5問ごとに任意で終了できる。
- **BLITZ:** 90秒の短時間挑戦。原則として短文の択一問題だけを出題し、先に学習済みの問題を優先する。選択肢を1回押すと即判定・ゲームスコア反映・短い演出で次問へ進む。時間切れをまたぐタップ、背景化後の復帰、二重タップで不正な加点をしない。終了時に正答率・コンボ・自己ベストと誤答解説を表示。速度は学習の習得率と混同しない。
- **独立したスコア:** Quest Run のランHP、攻撃、スキル、BLITZのアーケードスコアと自己ベストは**プレゼンテーションとラン成績用**。学習XP/正答回数/復習/既存キャンペーンは引き続き `applyStudyAttempt` のみが更新する。ゲームの複数効果で通常学習報酬を上乗せせず、同日同問題のXP/敵ダメージ重複を防ぐ。演出上の敵と正規キャンペーン進行を誤認させない。
- **学習上の整合性:** 既存問題の正誤キー・ID・説明・公式参照をそのまま使い、通常学習とQUEST RUNでは解説を読める。BLITZでは集中のため解説を回答直後に強制せず、終了後にすべての誤答を復習できる。BLITZの新規問題不足時は十分な出題数がないことを明示し、正答率から定着を推定しない。短文というだけで問題が初見学習に適していると主張しない。
- **失敗と終了:** プレイ途中でもホームへ戻れる。模試は新モードに含めず従来の独立採点を維持する。入力・採点は既存の一意receiptで管理し、既存の保存競合／復元保護中は新モードを開始できない。Web Audio / 振動 / reduced motion の既存設定に従う。
- **受入検査:** 純粋関数で問題選出、15問内の重複防止、3ステージ境界、ランHP、スキルの独立性、BLITZ適性、ゲームスコアを検証。React SSRでモード画面を描画し、PR CIにて全体buildを確認する。実スマホの音・触感は別途検証する。

## OVERDRIVE REFORGED — 主力学習ループ（2026-11）

- ホームの先頭に **REFORGED ARENA** を置き、最大5問で区切る。出題は既存 `planDailyFive` の期限到来・過去の誤答・未学習の優先順位を再利用する。アリーナ開始時の問題ID・選出理由・順序はセッション中に固定し、学習履歴の更新で現在の設問が差し替わらない。空プールでは問題なしを示す。
- 1問の操作は **確信度の自己予測 → 選択肢の確定 → 正解構成と理由の開示 → 任意の直後再構成 → 次へ**。択一・複数選択とも既存の正解キーで重複のない完全一致判定を行う。選択肢表示順は問題ごとにシャッフルし、見えるA/B/C等のラベルは表示位置に応じて連番とする。保存する回答は元の選択肢インデックスで、解答後の正解ラベルも実際の表示順に対応し、解答前に正解を表示しない。
- **通常の回答確定のみ**、`applyStudyAttempt` に一度送信する。モード `daily`、`boss=false`、セッションごとの `runId + index + questionId` を安定したreceiptとし、既存のXP・日付付き回答履歴・復習予定・敵HP・日次契約を正本として更新する。アリーナ独自のXP計算・報酬保存・別学習履歴は作らない。同日同問題の再挑戦では既存ロジックどおり基本XPと敵ダメージを付与しない。
- 模試・ボスの専用報酬とアリーナを混同しない。アリーナは模試でも既存10問分野ボスでもない。模試の独立採点や既存ボスのB/A/S・報酬条件は変更しない。
- アリーナ内の**直後再構成**は、解説を読んだ後に再度選択肢を選ぶ任意の確認。即時記憶の練習であり、**追加の学習イベント・XP・敵ダメージ・復習間隔更新は行わない**。成功しても遅延再想起や知識の定着とみなさない。
- 回答ごとの演出は実際の `applyStudyAttempt` 結果に従う。既存9体のSVG敵を現在のキャンペーン記録から表示し、ダメージなし・同日復習・誤答を「敵を倒した」と偽装せず、実HP・獲得XP・実ダメージ・討伐を文字で示す。音は既存の任意設定、動きはOSの動き軽減と既存VISUAL POWERに従う。アリーナの上部に音（SE）とFXの即時切替を設け、音の初期オフ・動き軽減の利用者設定を尊重する。動き軽減中はFXを有効化できない。問題文・公式リンク・答え合わせの読みやすさを優先する。
- 結果に **DOMAIN INTEL**（4分野の観測履歴）を読み取り専用で表示する。設問カタログに存在するIDへ照合した非模試の回答ログから、観測済みの異なる問題数、既存の復習予定から期限到来数、既存の誤答一覧から苦手数を集計する。別日の期限到来復習成功は、同一IDの非模試の先行ログが前日以前に存在し、後日の `due && correct` の非模試ログがある場合に限り、異なる問題IDごとに1件と数える。未来の記録、時刻と日付が矛盾する記録、模試ログを含めず、回答ログ未観測は0%習得とせず未観測と示す。ログは最大3000件であり、古い記録は復元しない。
- 結果には正答数、確信ありでの誤答、自信なしでの正答、直後再構成の成功数、誤答した問題IDを区別して示す。**いずれもAWS試験の換算点・合格予測・長期定着率ではない**。5問終了後は「今日はここで終了」を主操作とし、続行を強制しない。中断時に既に確定した回答の進捗は保持するが、未確定操作は破棄してよい。
- 既存の進捗は `useProgressConflict` が所有する保存・競合保護を経由する。保存復旧待ちや他タブ競合ではアリーナから新しい回答を書き込まない。旧v1ミッション・模試途中保存、v1/v2バックアップ、安定した問題IDを変更・初期化しない。既存保存中のミッションと並行してアリーナを開いても、その途中保存を上書きしない。
- アリーナは `src/ReforgeArena.tsx`、選出と正誤ロジックは `src/reforgeEngine.ts`、既存学習状態への変更は `src/main.tsx` が `applyStudyAttempt` に委譲する。画面幅320/360/400px、44px以上の操作対象、キーボードフォーカス、文字による正誤提示、動き軽減、任意終了を維持する。独立AWS有識者による検証・実Android機/ブラウザE2Eは実施した場合だけ成功を報告する。

- 比較の開閉はReactコンポーネント内だけの一時状態とし、問題IDが変わると初期化する。XP、報酬、復習間隔、採点、模試、問題ソース、学習記録、保存スキーマを変更しない。
- 説明は本文と色以外の文字情報で伝え、画面幅320pxでも折り返し、キーボードフォーカスおよびreduced-motion設定を維持する。

## 9. Phase 8 — MASTER QUEST（合意済み将来仕様・**未実装**）

**状態:** この節は次期開発の受入契約であり、現行公開版にBOSS INTELが実装済みであることを意味しない。実装・公開は個別PR、回帰テスト、CI、Pagesの成功後にのみ宣言する。実装順序と依存関係は [Phase 8実装計画](PHASE8_IMPLEMENTATION_PLAN.md) を参照する。

### 9.1 体験原則・日々の学習ループ

- **学習とRPGは単一の成果記録を共有する。** 通常ミッション、今日の5分クエスト、SMART QUEST、RECALL RAID、弱点復習、シナリオ練習での既存の解答イベントが、知識の観測証拠にもなる。ボス・遠征での非模試回答も、イベントから識別できる範囲では学習の観測として扱う。設計ラボ固有の判断記録は、別途出所を正確に識別できる対応が入るまで混ぜない。
- 1日の標準入口は既存の **Daily Five（最大5問）**。現在の選題方針（期限到来2・以前の苦手1・新規2を目標、不足時は利用可能な候補で補完）を維持する。解答→根拠確認→成果反映→終了または任意継続とし、クリア後の強制継続や新規通知は設けない。
- 「問題に正解した数」「誤答の回復」「日をまたいで思い出せた数」は別の測定値とする。XP・ランク・総回答数を理解度やAWS公式試験の合格予測に換算しない。

### 9.2 CONCEPT MAP（問題と知識の対応）

- 既存の348問の**安定した問題ID**に対して、静的・版管理された `conceptId` を関連付ける。概念は「IAM/STS信頼関係」「S3ストレージクラス」「RDS Multi-AZ」など、サービス名より狭い**判断観点**を表す。原則として各概念は主たるAWS SAA分野とボスを一つ持ち、複数概念に該当する設問は根拠付きで1対多マッピングを許可する。
- 概念カタログとマッピングには概念ID、表示名、分野、対応ボス、AWS公式参照、対象問題ID、根拠、版を保持する。**確定したマッピングのみ**BOSS INTELの数値に使う。自動抽出・キーワード一致は候補に限り、未検証の紐付けを知識習得の証拠として表示しない。実装初期は重点20〜30問を対象に始め、残りは未対応と表示してよい。
初期の概念カタログは各ボスに次の3観点を用意し、当該問題のAWS公式参照と選択肢の根拠を確認できたものだけを表示に採用する。対応する問題が不足するときは「未対応」と表示し、架空の進捗を置かない。

| 分野ボス | 初期CONCEPT MAP（固定conceptIdと判断観点） |
| --- | --- |
| CERBERUS／セキュリティ | `sec-iam-policy` IAMポリシー評価、`sec-sts-trust` STSと信頼関係、`sec-key-encryption` 鍵と暗号化 |
| PHOENIX／耐障害性 | `res-rds-ha` RDS高可用性、`res-dr-rto-rpo` DRとRTO/RPO、`res-route53-failover` DNS障害時切替 |
| TITAN／パフォーマンス | `perf-cdn-cache` CDN/キャッシュ、`perf-load-balance` 負荷分散、`perf-dynamodb-capacity` DynamoDB容量設計 |
| LEVIATHAN／コスト最適化 | `cost-s3-classes` S3ストレージ階層、`cost-compute-purchase` コンピュート購入選択、`cost-visibility` 利用状況・費用の可視化 |

- 概念と問題の対応を変更しても、保存済み問題ID、過去のXP、ボス記録、復習期限、勲章は変更しない。再集計による表示の変化は「現行マッピングに基づく表示」と明記し、永続的なアイテム解放や返還処理には直結させない。
- 概念の内容・誤答理由・AWS参照を確認するエンジニアリング作業は、**独立した有識者承認（現状0/348）と別の状態**として追跡する。

### 9.3 知識証拠の集計契約

- 主な入力は既存の端末ローカル `answerHistory`（最大3000イベント）と確定CONCEPT MAP。集計関数は**純粋・決定論的・読み取り専用**とし、日時は引数で固定できるようにする。模擬試験（`exam=true`）は通常の知識育成・攻略情報・XPへ算入しない。
- **初回正解:** 記録中に初回学習と示される非模試の正解イベントを、概念ごとに異なる問題IDで数える。**苦手克服:** `recovery=true` かつ正解である非模試イベントを異なる問題IDで数える。**期限到来の再想起:** 同じ問題IDについて、日付が異なる先行する非模試イベントと、後日の `due=true` かつ正解の非模試イベントを両方確認できるときのみ数える。単なる`due=true`、XP合計、連続日数、復習予定だけから成功を推定しない。
- 同一問題・同一証拠区分の再回答は証拠数を増殖させない。日をまたぐ日付判定にはアプリ既存のローカル暦日規則を使い、未来日・破損イベント・未知の概念IDを採用しない。1/3/7/14日指標は実際のイベント間隔を記録から確認できる場合のみ集計する。
- 過去の一部記録が存在しない、履歴の保存件数上限を超えた、マッピングが未確定である等の場合は**「未確認」「記録不足」「対応問題が未設定」**を表示する。「0問」と「証拠がない」を混同しない。計測範囲と対象問題数も併記する。過去の学習履歴を捏造・推定して補完しない。
- 初期版では知識証拠を既存履歴からの**派生表示**として扱い、新しい学習者データの保存キー・サーバー通信・別個のXP帳簿を増設しない。将来、ソースモードを厳密に分ける必要があれば、既存履歴にない属性は「不明」として安全に取り扱い、任意フィールドの追加は別PRで互換性を検証する。

### 9.4 BOSS INTEL — 10問ボスの既存仕様を固定

- 対象は4分野の既存ボス（CERBERUS／PHOENIX／TITAN／LEVIATHAN）。**各10問、7問正解で討伐（B）、9問でA、10問でS**とし、分野別出題・問題プール・保存済み最高記録・既存クリア記録の意味を変えない。
- **報酬は従来どおり**初討伐+400 XP、過去最高勲章からの昇格+120 XP、変化なしは追加討伐報酬なし。既存通常解答のXP判定と同日再回答制限も維持する。BOSS INTEL自体にはHP減算、正答扱い、倍率、ボーナスXP、アイテム配布、勲章解放を設定しない。
- ボスの「攻略情報」は対応概念ごとに **初回正解／苦手克服／日をまたいだ期限到来復習** の確認済み件数と対象数、次に学ぶべき関連観点を示す。これは出題対象の全知識の到達率や試験合格確率ではない。数字の根拠（該当する問題ID・ローカル学習日・証拠区分）を任意に確認できる。
- 知識の証拠が不足していても**ボス挑戦を禁止しない**。初回挑戦でも旧10問ボスにそのままアクセスできる。攻略情報は回答前の設計判断を思い出すためのヒントに限り、現在の10問の正解選択肢を公開しない。
- ボス挑戦前にINTELを参照し、挑戦中は攻略証拠の再集計や進行率表示を行わない。終了画面でのみ最新の観測証拠を再集計でき、次回の攻略準備につながる。セーブに新しいスナップショットを要求しない。INTELがオフでも採点・学習記録・XPは同一にする。

### 9.5 読みやすさとゲームの表示

- Android向けの320/360/400px表示を維持する。INTELはボスカード付近の**任意で開ける**小さな情報導線とし、Daily Fiveや問題本文より上に長大な一覧を挿入しない。展開したパネルはキーボードで利用可能、タップ対象は原則44px以上。
- 問題文・選択肢・解説は現行「文ごとに読む」・文字サイズ・集中／省スペース／詳細表示を維持し、**問題本文と正解データは加工しない**。条件・制約・問われている判断・理由は、視覚的に区切れる場合でも元文章を改変せず表示する。
- RPGの追加演出は集中表示・動きを減らす設定で抑制できる。情報は色やアニメーションのみで伝えず、テキストでも「未観測／観測あり／再想起あり」を説明する。過度な連続プレイ誘導や失敗日のペナルティーを追加しない。

### 9.6 移行・品質・検証ゲート

- `applyStudyAttempt` を唯一の通常解答XP/敵ダメージ更新経路として維持する。attempt receiptによる二重処理防止、模試と通常学習の分離、v1ミッション・模試保存、v1/v2バックアップ、ローカル複数タブ保護を退行させない。
- 対象問題の改善はAWS公式資料を根拠に原問題・選択肢・不正解理由を確認し、類似問題を減らす。ただし正答キー・問題の意味を変える修正は、既存IDに紐づく復習記録・誤答履歴の解釈を検討し、必要なら承認された移行仕様を先に用意する。問題数の水増しを目標にしない。
- 受入テストは概念ID整合性・未分類・多重紐付け・日付跨ぎ・不完全履歴・重複イベント・ボス10問B/A/S境界・既存報酬・同日再回答・模試隔離・保存互換・画面の情報順序・読書補助の原文保持を含む。
- `npm run build`／PR CI／master Pages公開の成功を出荷条件とする。**ブラウザE2E、実機Android/Brave確認、独立AWS有識者承認は継続して保留**し、実施したと主張しない。
