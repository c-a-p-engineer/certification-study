# CERTIFICATION//OVERDRIVE — 仕様書

**状態:** 現行実装を基準とする公開アプリの機能仕様。更新日: 2026-10-24。
**対象:** [AWS SAA-C03 向け学習アプリ](https://c-a-p-engineer.github.io/certification-study/)。
**管理:** `AGENTS.md` が変更時の同期手順を所有し、この文書が利用者から見た動作と受入条件を所有する。README は概要と入口であり、この仕様の複製ではない。

## 1. 目的と適用範囲

- オリジナルのAWS SAA練習問題と反復学習・模擬試験・設計判断の練習を、ゲームとして継続しやすくする。
- スマートフォン（320/360/400pxを含む狭い幅）で初回の行動をすぐ選べる。
- XP、モンスター討伐、称号は学習の動機づけであり、AWS認定合格率・公式スコアを示さない。
- 学習記録は端末内で保持する。サーバー同期、アカウント、オンラインLeaderboard、自動外部送信は対象外。

## 2. ホーム（初期画面）の情報設計

### 常に表示するもの

1. アプリ名・ランク・設定へのメニュー。
2. 現在の称号とレベル進捗。
3. 保存済み学習・模擬試験があれば、その再開導線。
4. **「今日の5分クエスト」**を明瞭な最優先学習アクションとして表示し、実行可能条件と問題数・出題理由を示す。
5. **「START MISSION」**（標準学習）と弱点復習の入口。
6. 本日のDAILY QUEST報酬状況、XP・正答率・復習期限・ベストコンボのコンパクトな進捗表示、オフライン状態。

### 初期状態では閉じるもの

| 開閉パネル | 内包する機能 | 表示条件 |
| --- | --- | --- |
| 問題数・分野・模擬試験などを選ぶ | 分野、10/20/無制限、65問模擬試験、シナリオ問題、能動想起、復習、ボス選択 | ホーム上で任意に展開 |
| 冒険・設計チャレンジ | モンスター、5遠征、AWS設計シミュレーター | 任意に展開 |
| もっと学習する | RECALL RAID、SMART QUEST、BOSS RUSH | 任意に展開 |
| 学習記録・成長分析 | 学習タイムライン、成長グラフ、学習分析 | 任意に展開 |
| スキル・コレクション | スキルツリー、レリック、習熟度、問題カバレッジ | 任意に展開 |

- 各パネルはネイティブの `details/summary` でキーボードからも展開可能とし、画面幅やJavaScriptの追加状態保存に依存しない。
- 閉じているパネルは、長大なコンテンツを初期スクロール上へ露出させない。パネルを開けば従来の各機能を利用できる。
- 隠したパネルの機能を削除しない。標準学習・5分クエスト・復旧の導線は隠さない。
- ホーム表示変更のみでXP・問題ID・進捗・保存schemaの意味を変えない。
- 視覚効果削減設定を尊重する。開閉には予測不能な報酬やゲーム強制遷移を追加しない。

## 3. 学習セッション

- 問題バンクは **348問**、うち長めのシナリオ形式 **48問**。4分野（セキュリティ・耐障害性・パフォーマンス・コスト最適化）。選択肢順序はセッション内でシャッフルし、複数選択は正解集合との完全一致で採点する。
- 通常学習は分野選択、10問・20問・無制限の出題数を提供する。間違い復習とシナリオ限定学習も提供する。
- `今日の5分クエスト` は最大5問の任意セッション。期限到来した前日以前の復習、過去の誤答、未学習を基準に重複IDなしで選び、対象が足りなければ実問数を示す。完了後に明確な終了操作があり、自動的に次のセッションを開始しない。
- 65問模擬試験は130分の制限時間を持ち、演習とは採点・履歴・経験値を分離する。後から1問ずつ解説とAWS公式参照を確認できる。
- 用語解説には読み方・説明を含め、必要時に展開できる。読みやすさのため文字サイズとフォーカス表示を変更できる。

## 4. 学習効果と報酬

- `applyStudyAttempt` は副作用のない解答トランザクションを提供する。保存済みrunIdと最大1024件のreceiptにより同一解答イベントの再加算を防ぐ。
- 同じ暦日の同じ問題への再正解は基本XP・敵ダメージを加算せず、正解復習連続回数を伸ばさない。模擬試験の解答は訓練XP・敵HP・日次報酬・訓練復習予定を更新しない。既存XPの遡及変更はしない。
- 5種類の分野別遠征、9種の敵とNG+、8件×各3段階の設計判断演習は任意のゲーム/学習モード。実力認定や公式AWSの審査と混同しない。
- 間隔復習とRETENTION LABの1/3/7/14日統計は、日付付き実観測とサンプル数を示す。未計測期間を補完したり、合格確率や学習効果の因果を断定したりしない。
- 問題の独立した有識者承認は現時点で **0/348件**。AWS公式資料へのリンク、AI生成の解説、既存の編集日付は独立承認の代わりにならない。

### OVERDRIVE 7.3：アーキテクチャ判断の再演習

- 既存4ケースに、リージョンDR（RTO/RPO）、S3のストレージ階層、OrganizationsのSCP/IAM、Lambda + SQSの失敗処理を加え、計8ケース・各3判断とする。
- 各判断は3択、要件・根拠・選択肢別フィードバック・AWS公式参照を提供する。概念図は要素一覧であり、通信順序や正確なトポロジーを主張しない。
- ケース終了時に誤ったstep IDを `designLab.reviewDue` の最大40件の任意ローカル記録へ保持し、次の**ローカル暦日**から設計ラボに**対象stepだけの単問復習**を表示する。単問復習では通常の3ステップケース完成記録・ベスト成績・勲章を更新しない。正しく再判断したstepはリストから除外し、同じstepの未修得記録は1件に集約する。
- `caseId:stepId` が出所を識別する。これは**設計演習専用の復習予定**であり、348問の通常の質問ID、review scheduling、通常XP、模試成績を変更しない。過去の設計記録に誤答履歴が無い場合は復元・推測しない。
- v1/v2バックアップに既存 `designLab` の追加任意フィールドを含められ、保存入力時には出所・件数・step有効性を確認する。実デバイスE2Eと独立有識者レビューは未完了。

### OVERDRIVE 7.2：任意の遠征チェーン・収集

- 既存の5遠征（各5問）に、問題のindexと同じ5段階の進行表示（索敵・遭遇・対策・反撃・決戦）を付ける。既存v1 missionの保存indexから自動再現でき、新しい進捗キーを導入しない。
- 遠征でのみ敵SVGと次の設計観点を示す。集中表示では非表示、320px級画面でも回答領域を圧迫しない。演出に追加のランダム性・待機時間・報酬倍率を導入しない。
- 収集段階は（1）異なる探索先1つクリア、（2）異なる探索先3つクリア、（3）全5つクリア＋翌日以降の復習成功から獲得したレアエンブレム2種、の証跡から導出する。周回回数だけではレア報酬は増えず、追加XPも与えない。
- このコレクションはクリア履歴からの派生表示で、保存データの形式を変更しない。遠征が苦手なら利用しなくても通常学習・5分クエストを使える。

## 5. ローカルデータ・復旧

- progress、日付付き回答履歴、学習セッション、模試の途中状態等はブラウザのローカル領域に保存される。
- v1/v2 JSONバックアップの互換インポートとv2 SHA-256破損検出（署名ではない）を維持し、復元処理のjournalが残れば自動保存を止めて元データを守る。
- 複数タブで外部変更を検出した場合、古いタブの自動保存を停止し、機密を含むJSON退避と最新記録の再読込を案内する。Web Locksが利用できる場合に限り協調する書込を直列化する。非対応環境で原子的な競合排除は保証しない。
- ブラウザのキャッシュ削除やデータ消去を復旧の既定策にしない。
- PWAのキャッシュ後はオフラインで出題可能。ただし外部AWSドキュメントはオフラインで提供されない。

## 6. アクセシビリティと表示

- Android/Braveなどのモバイル閲覧を想定し、320px幅までの狭い画面で横溢れを抑え、学習問題・回答の可読性を優先する。
- 開閉操作・解答・次へ・メニューにキーボードで到達できる。操作可能要素のタップ領域は原則44px以上とし、focus-visibleとreduced motionを維持する。
- ホームの開閉によってクイズの読込や採点、セッション復帰に影響を与えない。
- クイズ問題文の長文視認性を優先し、通常表示でも過度な太字を避け、選択肢本文を軽めのウェイトで描画する。文字の大きさは従来の5段階設定を維持する。
- 問題分野の横に **「文ごとに読む」** を配置し、押すと問題の句点・疑問符・感嘆符で視覚的なまとまりに区切り、行間と段落間隔、左側の細いガイド、読みやすい行幅を適用する。もう一度押すと「通常表示へ」戻せる。操作は44px以上、状態は `aria-pressed` で伝える。
- 長い選択肢も同じ読み方設定を使用し、複数の文がある場合に限り文間の視覚的余白を加える。答えのボタンや選択位置は変更しない。
- 文章の分割は**表示専用**であり、元の問題文字列は改変しない。問題文・正答・選択肢・ChatGPTへコピーする素材・問題ID・採点・XP・模試の保存に影響を与えない。問題文の結合順序、句読点、空白を保持する。
- 設定は別キー `cert-overdrive-reading-guide-v1` に端末ローカルで任意保存し、初期値はオフ。保存不可・不正値でも正常表示を維持し、既存バックアップのスキーマは変更しない。

## 9. Phase 8 — MASTER QUEST（合意済み将来仕様・**未実装**）

**状態:** この節は次期開発の受入契約であり、現行公開版にBOSS INTELが実装済みであることを意味しない。実装・公開は個別PR、回帰テスト、CI、Pagesの成功後にのみ宣言する。実装順序と依存関係は [Phase 8実装計画](PHASE8_IMPLEMENTATION_PLAN.md) を参照する。

### 9.1 体験原則・日々の学習ループ

- **学習とRPGは単一の成果記録を共有する。** 通常ミッション、今日の5分クエスト、SMART QUEST、RECALL RAID、弱点復習、シナリオ練習での既存の解答イベントが、知識の観測証拠にもなる。ボス・遠征での非模試回答も、イベントから識別できる範囲では学習の観測として扱う。設計ラボ固有の判断記録は、別途出所を正確に識別できる対応が入るまで混ぜない。
- 1日の標準入口は既存の **Daily Five（最大5問）**。現在の選題方針（期限到来2・以前の苦手1・新規2を目標、不足時は利用可能な候補で補完）を維持する。解答→根拠確認→成果反映→終了または任意継続とし、クリア後の強制継続や新規通知は設けない。
- 「問題に正解した数」「誤答の回復」「日をまたいで思い出せた数」は別の測定値とする。XP・ランク・総回答数を理解度やAWS公式試験の合格予測に換算しない。

### 9.2 CONCEPT MAP（問題と知識の対応）

- 既存の348問の**安定した問題ID**に対して、静的・版管理された `conceptId` を関連付ける。概念は「IAM/STS信頼関係」「S3ストレージクラス」「RDS Multi-AZ」など、サービス名より狭い**判断観点**を表す。原則として各概念は主たるAWS SAA分野とボスを一つ持ち、複数概念に該当する設問は根拠付きで1対多マッピングを許可する。
- 概念カタログとマッピングには概念ID、表示名、分野、対応ボス、AWS公式参照、対象問題ID、根拠、版を保持する。**確定したマッピングのみ**BOSS INTELの数値に使う。自動抽出・キーワード一致は候補に限り、未検証の紐付けを知識習得の証拠として表示しない。実装初期は重点20〜30問を対象に始め、残りは未対応と表示してよい。
- 概念と問題の対応を変更しても、保存済み問題ID、過去のXP、ボス記録、復習期限、勲章は変更しない。再集計による表示の変化は「現行マッピングに基づく表示」と明記し、永続的なアイテム解放や返還処理には直結させない。
- 概念の内容・誤答理由・AWS参照を確認するエンジニアリング作業は、**独立した有識者承認（現状0/348）と別の状態**として追跡する。

### 9.3 知識証拠の集計契約

- 主な入力は既存の端末ローカル `answerHistory`（最大3000イベント）と確定CONCEPT MAP。集計関数は**純粋・決定論的・読み取り専用**とし、日時は引数で固定できるようにする。模擬試験（`exam=true`）は通常の知識育成・攻略情報・XPへ算入しない。
- **初回正解:** 記録中に初回学習と示される非模試の正解イベントを、概念ごとに異なる問題IDで数える。**苦手克服:** `recovery=true` かつ正解である非模試イベントを異なる問題IDで数える。**期限到来の再想起:** 同じ問題IDについて、日付が異なる先行する非模試イベントと、後日の `due=true` かつ正解の非模試イベントを両方確認できるときのみ数える。単なる`due=true`、XP合計、連続日数、復習予定だけから成功を推定しない。
- 同一問題・同一証拠区分の再回答は証拠数を増殖させない。日をまたぐ日付判定にはアプリ既存のローカル暦日規則を使い、未来日・破損イベント・未知の概念IDを採用しない。1/3/7/14日指標は実際のイベント間隔を記録から確認できる場合のみ集計する。
- 過去の一部記録が存在しない、履歴の保存件数上限を超えた、マッピングが未確定である等の場合は**「未確認」「記録不足」「対応問題が未設定」**を表示する。「0問」と「証拠がない」を混同しない。計測範囲と対象問題数も併記する。過去の学習履歴を捏造・推定して補完しない。
- 初期版では知識証拠を既存履歴からの**派生表示**として扱い、新しい学習者データの保存キー・サーバー通信・別個のXP帳簿を増設しない。将来、ソースモードを厳密に分ける必要があれば、既存履歴にない属性は「不明」として安全に取り扱い、任意フィールドの追加は別PRで互換性を検証する。

### 9.4 BOSS INTEL — 10問ボスの既存仕様を固定

- 対象は4分野の既存ボス（CERBERUS／PHOENIX／TITAN／LEVIATHAN）。**各10問、7問正解で討伐（B）、9問でA、10問でS**とし、分野別出題・問題プール・保存済み最高記録・既存クリア記録の意味を変えない。
- **報酬は従来どおり**初討伐+400 XP、過去最高勲章からの昇格+120 XP、変化なしは追加討伐報酬なし。既存通常解答のXP判定と同日再回答制限も維持する。BOSS INTEL自体にはHP減算、正答扱い、倍率、ボーナスXP、アイテム配布、勲章解放を設定しない。
- ボスの「攻略情報」は対応概念ごとに **初回正解／苦手克服／日をまたいだ期限到来復習** の確認済み件数と対象数、次に学ぶべき関連観点を示す。これは出題対象の全知識の到達率や試験合格確率ではない。数字の根拠（該当する問題ID・ローカル学習日・証拠区分）を任意に確認できる。
- 知識の証拠が不足していても**ボス挑戦を禁止しない**。初回挑戦でも旧10問ボスにそのままアクセスできる。攻略情報は回答前の設計判断を思い出すためのヒントに限り、現在の10問の正解選択肢を公開しない。
- ボス挑戦中に参照するINTELは開始時点の表示スナップショットとして扱い、回答によって攻略段階や数値が突然変わらない。終了画面では最新の観測証拠を確認でき、次回の攻略準備につながる。INTELがオフでも採点・学習記録・XPは同一にする。

### 9.5 読みやすさとゲームの表示

- Android向けの320/360/400px表示を維持する。INTELはボスカード付近の**任意で開ける**小さな情報導線とし、Daily Fiveや問題本文より上に長大な一覧を挿入しない。展開したパネルはキーボードで利用可能、タップ対象は原則44px以上。
- 問題文・選択肢・解説は現行「文ごとに読む」・文字サイズ・集中／省スペース／詳細表示を維持し、**問題本文と正解データは加工しない**。条件・制約・問われている判断・理由は、視覚的に区切れる場合でも元文章を改変せず表示する。
- RPGの追加演出は集中表示・動きを減らす設定で抑制できる。情報は色やアニメーションのみで伝えず、テキストでも「未観測／観測あり／再想起あり」を説明する。過度な連続プレイ誘導や失敗日のペナルティーを追加しない。

### 9.6 移行・品質・検証ゲート

- `applyStudyAttempt` を唯一の通常解答XP/敵ダメージ更新経路として維持する。attempt receiptによる二重処理防止、模試と通常学習の分離、v1ミッション・模試保存、v1/v2バックアップ、ローカル複数タブ保護を退行させない。
- 対象問題の改善はAWS公式資料を根拠に原問題・選択肢・不正解理由を確認し、類似問題を減らす。ただし正答キー・問題の意味を変える修正は、既存IDに紐づく復習記録・誤答履歴の解釈を検討し、必要なら承認された移行仕様を先に用意する。問題数の水増しを目標にしない。
- 受入テストは概念ID整合性・未分類・多重紐付け・日付跨ぎ・不完全履歴・重複イベント・ボス10問B/A/S境界・既存報酬・同日再回答・模試隔離・保存互換・画面の情報順序・読書補助の原文保持を含む。
- `npm run build`／PR CI／master Pages公開の成功を出荷条件とする。**ブラウザE2E、実機Android/Brave確認、独立AWS有識者承認は継続して保留**し、実施したと主張しない。
